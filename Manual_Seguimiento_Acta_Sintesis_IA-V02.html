Sección 1

Introducción y objeto

La pestaña «Seguimiento», dentro del módulo de Consultoría/Implantación, permite gestionar las reuniones con el cliente a lo largo de todo el proyecto. La Inteligencia Artificial (IA) automatiza las partes más costosas en tiempo: leer el acta, redactar el resumen y extraer las tareas.

Este manual cubre el uso completo de las funciones IA integradas en la plataforma: síntesis de actas, resumen global, extracción de tareas y gestión del seguimiento.

¿Qué puedes hacer con la IA en esta pestaña?

✨ Sintetizar acta
Genera un resumen de ~10 líneas a partir del .docx, .pdf o .txt subido.
📋 Extraer tareas
La IA detecta y crea las tareas con responsable y fecha límite automáticamente.
📊 Resumen global
Resumen ejecutivo de todas las actas del proyecto en un solo clic.
🔄 Seguimiento
Gestión de estados, acciones de resolución e historial completo de cada tarea.

Sección 3

Cómo trabaja la IA aquí

3.1 Modo automático (con API Key) — Recomendado

Configuras una API Key una vez. Al pulsar «Sintetizar», la aplicación llama directamente al servicio de IA y rellena el resumen y las tareas. No necesitas salir de la aplicación.

Proveedor recomendado: Groq
Desde v2.0 (octubre 2026), Groq es el proveedor corporativo por defecto. Sus modelos (openai/gpt-oss-20b, openai/gpt-oss-120b) son propios de Groq — no dependen de terceros y no rotan sin aviso. Velocidad: 1.000 tokens/segundo. Gratuito con key propia (gsk_...). Crea tu key en console.groq.com/keys.

3.2 Modo manual (sin API Key — flujo de respaldo)

Si no hay API Key configurada, la aplicación muestra el modal «Prompt para la IA». El prompt ya está copiado al portapapeles automáticamente. Puedes pegarlo en ChatGPT, Claude u otro servicio externo y luego pegar el resultado con el botón «Pegar resultado IA».

Si aparece el modal teniendo API Key configurada
La key corporativa se carga de forma asíncrona desde el servidor. Si pulsas «Sintetizar» muy rápido al cargar la página, puede que la key aún no esté disponible. Cierra el modal y vuelve a pulsar «Sintetizar» — en la segunda llamada ya estará cargada.

3.3 Key corporativa compartida en LAN GROQ v2.0

El administrador configura la API Key corporativa una sola vez desde el panel «Configuración IA» de plataforma-seguimiento.html. Esta clave se almacena en el servidor Flask (plataforma.db) y es automáticamente usada por todos los PCs de la red.

  • La key se ofusca con XOR+base64 antes de guardarse — no se almacena en texto plano
  • La clave XOR es fija e independiente del hostname — funciona desde localhost, 127.0.0.1 o cualquier IP de la LAN
  • Si un usuario configura su propia key personal, ésta tiene prioridad sobre la corporativa
  • Proveedor corporativo actual: Groq con modelo openai/gpt-oss-20b

3.4 Prioridad de configuración

PrioridadTipoDónde se guardaVisible desde
1ºKey personallocalStorage del navegadorSolo ese PC y ese navegador
2ºKey corporativaplataforma.db (servidor Flask)Cualquier PC de la LAN
3ºDefault (Groq)Código fuente (llm.js)Si no hay key personal ni corporativa

Sección 5

Configurar la IA

5.1 Configuración personal (por navegador)

La configuración personal se guarda en el localStorage del navegador del PC donde se configura. Solo es visible desde ese PC y ese navegador.

  1. Abre el proyecto → pestaña «Seguimiento»
  2. El panel «🔑 Configuración API (LLM)» aparece arriba
  3. Elige proveedor
    Recomendado: Groq. Crea tu key en console.groq.com/keys (gratis, sin tarjeta).
  4. Pega la API Key en el campo «API Key»
  5. Pulsa «Probar conexión»
    Debe aparecer «✔ OK» con el nombre del modelo.
  6. La configuración se guarda automáticamente al escribir

5.2 Configuración corporativa compartida en LAN RECOMENDADA

El administrador configura la key una vez y todos los PCs de la red la usan automáticamente. No es necesario configurar nada en cada PC.

  1. Abre http://192.168.x.x:5001 (IP del servidor Flask)
  2. Ve a la sección lateral «Configuración IA»
  3. Elige proveedor Groq, pega la API Key y pulsa «Guardar»
  4. Todos los PCs de la LAN usarán esta key automáticamente
    No es necesario reiniciar el servidor.
Prioridad
Si un usuario configura su propia key personal en la app, ésta tiene prioridad sobre la key corporativa. Para volver a usar la corporativa: borrar la key personal del campo API Key en la app.

5.3 Ollama (IA local, sin internet)

Ollama ejecuta modelos de IA localmente. No requiere API Key ni conexión a internet. Ideal para datos confidenciales.

  • Instalar Ollama: ollama.ai
  • Para acceso desde otros PCs de la LAN: OLLAMA_HOST=0.0.0.0 ollama serve
  • En la app: seleccionar proveedor «Ollama (Local)» — el campo API Key se rellena solo con ollama
  • Pulsar «Detectar» para listar los modelos instalados
ModeloTamañoPara qué

qwen3:8b5 GBUso general — rápido

Sección 6

Sintetizar un acta de reunión

6.1 Flujo con API Key configurada

  1. Abre la reunión (clic en «▼ Abrir acta»)
    Se expande el panel del acta con los campos de síntesis.
  2. Pulsa «Subir acta» y selecciona el fichero .docx, .pdf o .txt
    El nombre del fichero queda visible junto al botón.
  3. Pulsa «✨ Sintetizar»
    Toast «Procesando...» y spinner mientras la IA trabaja.
  4. Espera unos segundos (hasta 30 s con modelos gratuitos)
    Resumen (~10 líneas) y tareas extraídas y rellenadas automáticamente.
  5. Revisa y ajusta responsables y fechas si es necesario
    Los cambios se guardan automáticamente.
Reintentos automáticos
La aplicación reintenta automáticamente hasta 2 veces si la llamada falla por saturación (error 429) o servidor caído (503). Si ya hay contenido guardado, aparecerá el modal de confirmación «¿Sobrescribir con la propuesta de la IA?» — esto es el comportamiento correcto.

6.2 Flujo sin API Key (modo manual de respaldo)

  1. Pulsa «✨ Sintetizar» → aparece el modal «Prompt para la IA»
    El prompt ya está copiado al portapapeles automáticamente.
  2. Abre ChatGPT, Claude o cualquier IA en el navegador
  3. Pega el prompt (⌘V) y envía
  4. Copia el JSON que devuelve la IA
  5. En la app: pulsa «Pegar resultado IA» → pega el JSON → «Aplicar»
    Los campos se rellenan igual que en modo automático.
Sección 7

Resumen global de actas

La función «Generar Resumen IA» (pestaña Diseño, sección Actas) genera un resumen ejecutivo de todas las actas del proyecto en un único texto. Es útil para informes de progreso y reuniones de dirección.

  1. Ve a la pestaña «Diseño SGSI» (o «Diseño» en otras normas)
  2. Sube una o más actas en la sección «Actas de consultoría»
  3. Pulsa «Generar Resumen IA» junto al listado de actas
  4. La IA genera un resumen 3-5 puntos por acta y un ejecutivo global
    El resultado se muestra en el panel y se puede copiar o guardar.
El botón aparece siempre
Desde v1.1, el botón «Generar Resumen IA» aparece siempre que hay un fichero subido, aunque no haya API Key. Si no hay key, muestra el modal de prompt manual de respaldo.
Sección 8

Gestión y seguimiento de tareas

Cada tarea incluye: título, descripción, responsable, fecha límite, estado e indicador C (CODANOR) si fue propuesta por la IA. Las tareas nunca se borran — se pueden consultar filtrando por estado.

8.1 Estados de tarea

EstadoDescripciónAcciones disponibles
En cursoTarea activa en progresoCompletar · Desestimar
A revisarPendiente de revisión por el responsableCompletar · Desestimar
CompletadaCerrada con éxito — fecha de cierre registradaReabrir
DesestimadaDescartada con motivo obligatorio registradoReabrir
VencidaFecha límite superada sin cerrarCompletar · Desestimar

8.2 Acciones de resolución (sub-pasos)

Cada tarea puede tener acciones de resolución intermedias — los pasos concretos para cerrarla. Se accede con el botón 📋 de cada tarea en el panel de seguimiento.

CampoDescripción
DescripciónTexto libre describiendo la acción a realizar
ResponsablePersona o rol responsable de esta acción concreta
EstadoPendiente En curso Resuelta
Cerrada elFecha de cierre automática al marcar como «Resuelta»
Restricción
No se pueden añadir ni editar acciones cuando la tarea está en estado Completada o Desestimada. Réabrela primero si necesitas añadir más pasos.

8.3 Historial de cambios

Cada cambio de estado (completar, desestimar, reabrir) queda registrado en el historial de la tarea con: fecha, acción y nota opcional. El historial es visible en el panel de detalle de la tarea y nunca se puede borrar — es el registro de auditoría.

Sección 9

Acceso desde la LAN (varios PCs)

El servidor Flask escucha en 0.0.0.0:5001 — accesible desde cualquier PC de la red local.

9.1 URLs de acceso

DesdeURL
El servidor mismohttp://localhost:5001 o http://127.0.0.1:5001
Otro PC de la LANhttp://192.168.x.x:5001 (IP del servidor)
Pantalla de inicio (9 normas)http://192.168.x.x:5001/
App ENS directahttp://192.168.x.x:5001/ens/

9.2 localStorage vs key corporativa

El localStorage del navegador es estrictamente por origen (localhost ≠ 127.0.0.1 ≠ IP de red). Por tanto:

  • La key personal configurada en localhost NO es visible desde 127.0.0.1 ni desde la IP de red
  • La key corporativa (guardada en el servidor) SÍ es visible desde cualquier origen
  • Recomendación en entornos LAN multiusuario: usar siempre la key corporativa
  • Si un usuario quiere una key personal diferente: configúrala en la app — tiene prioridad sobre la corporativa
Importante
Nunca mezcles acceso por localhost y por IP en la misma sesión para la misma key personal — son orígenes distintos y el navegador no compartirá el localStorage.

La IA devuelve textos de ejemplo en lugar del contenido del acta Modelo poco potente o acta con muy poco texto Usar un modelo mejor (llama-3.3-70b-versatile, gemini-2.0-flash, openai/gpt-oss-20b) o revisar que el acta tiene contenido real.
El resumen tarda más de 30 segundos Normal con modelos gratuitos en horas punta La app espera hasta 90 s y reintenta una vez. Para mayor velocidad usar Groq (1.000 t/s).
Las columnas de acciones muestran texto tipo PHASE2.ACCIONDESCRIPCION Versión anterior del módulo con claves i18n ausentes Recargar la página — la versión v20261007b incluye todas las traducciones.
«✨ Sintetizar» no aparece en la reunión La reunión no tiene acta subida ni notas escritas Subir el fichero del acta con «Subir acta» o escribir notas en el campo de texto.
Sección 11 NUEVO v2.0

Mantenimiento y actualización de este manual

Esta sección define cuándo actualizar el manual, qué cambiar y cómo publicarlo. El objetivo es que el manual esté siempre sincronizado con el estado real del sistema.

11.1 Cuándo actualizar

Cambios que requieren actualización inmediata

  • Cambio de proveedor corporativo por defecto
  • Nuevos proveedores o modelos soportados
  • Cambio en el flujo de «Sintetizar» (pasos, botones, modales)
  • Cambios en la URL o estructura del servidor Flask
  • Nuevas funciones IA (ej: resumen global, consulta wiki)
  • Corrección de errores documentados en la sección 10

Cambios que pueden esperar a la próxima versión

  • Actualización de la cadena FREE_FALLBACK_CHAIN
  • Cambios menores de UI (iconos, colores, textos de botones)
  • Nuevas apps ISO/ENS añadidas a la plataforma
  • Correcciones tipográficas
  • Mejoras de la sección de resolución de problemas

11.2 Proceso de actualización

  1. Identificar el cambio que requiere actualización
    Ver tabla 11.1. Si afecta al flujo principal → actualización inmediata.
  2. Incrementar la versión en el control de versiones
    Regla: cambios de fondo → v2.x; cambios mayores estructurales → v3.0. Formato: vX.Y.
  3. Editar el archivo Manual_Seguimiento_Acta_Sintesis_IA-VXX.html
    Actualizar: control de versiones, sección afectada, cabecera (versión + fecha), pie de página.
  4. Añadir la fila en el control de versiones
    Versión | Fecha | Autor | Descripción del cambio.
  5. Actualizar AGENTS.md y Memory.md en PLATAFORMA_OpenCode-NEW
    Sección «Documentación generada» con la nueva versión y tamaño.
  6. Commit en Git
    Mensaje: docs: Manual_Seguimiento_Acta_Sintesis_IA-VXX.html — descripción breve

11.3 Nomenclatura de versiones del archivo

VersiónNombre de archivoCriterio
v2.0Manual_Seguimiento_Acta_Sintesis_IA-V02.htmlVersión actual — nuevo formato HTML, Groq por defecto
v2.1Manual_Seguimiento_Acta_Sintesis_IA-V02.htmlActualización menor — mismo archivo, nueva fila en control de versiones

Regla de nomenclatura
El sufijo -V02 del nombre de archivo solo cambia cuando el cambio es estructural (nueva versión mayor). Para actualizaciones menores dentro de la misma versión mayor, se edita el mismo archivo y se añade una fila al control de versiones.

11.4 Checklist pre-publicación

  • ☐ Control de versiones actualizado con nueva fila
  • ☐ Fecha actualizada en portada, cabecera y pie de página
  • ☐ Sección 10 (problemas) revisada — ¿hay nuevos problemas conocidos?
  • ☐ Sección 4 (proveedores) actualizada — ¿hay modelos nuevos o retirados?
  • ☐ Tabla de proveedores (sección 4) refleja el proveedor corporativo actual
  • ☐ AGENTS.md actualizado con la nueva versión del documento
  • ☐ Memory.md actualizado con la nueva versión del documento

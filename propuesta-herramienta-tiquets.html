Contexto y Objetivo

CODANOR actúa como responsable de Sistema de Gestión especializado en arquitectura de ciberseguridad y analista funcional senior, responsable de los proyectos de las diferentes normas ISO y marcos regulatorios aplicables a sus clientes. El portfolio actual cubre:

Norma / Marco Ámbito Clasificación
ISO 27001 — SGSISeguridad de la InformaciónCiberseguridad
ISO 27701 — SGPPrivacidad de la InformaciónCiberseguridad
ISO 42001 — SGIAGestión de Inteligencia ArtificialIA / Riesgo
TISAXSeguridad AutomotiveCiberseguridad
RGPD-LOPD-GDDProtección de DatosLegal
ISO 9001 — SGCCalidadCalidad
ISO 14001 — SGMA 2015/2026MedioambienteMedioambiente
ENS — RD311-2022Esquema Nacional de SeguridadCiberseguridad

Objetivo: diseñar e implementar una herramienta de ticketing multiplataforma que sirva para todas las normas anteriores, poniendo el foco en la ciberseguridad como disciplina más exigente. La herramienta deberá gestionar de forma unificada: incidencias, peticiones, cambios, problemas, vulnerabilidades y ciberincidentes, manteniendo la trazabilidad y las evidencias requeridas por cada marco normativo.

⚡ 9.3 — Lógica de Generación del ID (transacción atómica)

La función usa client_id (TEXT, de clients.id) y app_id (TEXT, de projects.app_id) — ambos ya existentes en plataforma.db. La transacción atómica garantiza que dos peticiones concurrentes nunca generen el mismo NNN para el mismo par cliente+norma.

Python servidor/routes_tiquets.py — generar_tiquet_id() 
from datetime import datetime

def generar_tiquet_id(client_id: str, app_id: str, conn) -> tuple[str, int]:
    """
    Genera ID único: TIK-{NNN:03d}-{client_id}-{app_id}-{DD-MM-AAAA}

    Parámetros tomados directamente de plataforma.db (ya existen):
      client_id : str  →  clients.id        (ej: "cli_703")
      app_id    : str  →  projects.app_id   (ej: "iso27001")

    Ejemplo de ID resultante:
      TIK-001-cli_703-iso27001-27-08-2026

    Garantía: transacción atómica ON CONFLICT DO UPDATE.
    Nunca se reutiliza ni se reinicia el NNN por par client_id+app_id.
    """
    with conn:  # BEGIN / COMMIT automático (WAL mode)
        # Paso 1 — Incrementar contador o crear si no existe (atómico)
        conn.execute("""
            INSERT INTO contadores_tiquets (client_id, app_id, ultimo_nnn)
            VALUES (?, ?, 1)
            ON CONFLICT(client_id, app_id)
            DO UPDATE SET ultimo_nnn = ultimo_nnn + 1
        """, (client_id, app_id))

        # Paso 2 — Leer el NNN asignado en esta transacción
        row = conn.execute("""
            SELECT ultimo_nnn
            FROM contadores_tiquets
            WHERE client_id = ? AND app_id = ?
        """, (client_id, app_id)).fetchone()

    nnn = row[0]
    fecha = datetime.now().strftime('%d-%m-%Y')
    tiquet_id = f"TIK-{nnn:03d}-{client_id}-{app_id}-{fecha}"
    return tiquet_id, nnn

📶 9.5 — Modo Offline / Fallback localStorage

La SPA detecta automáticamente si el servidor Flask está activo. Si no lo está (apertura directa con file:// o servidor detenido), opera en modo offline usando localStorage con el mismo modelo de datos.

JavaScript plataforma-seguimiento.html — detección online/offline 
const API_BASE = 'http://localhost:5500/api';
let modoOnline = false;

async function detectarModo() {
  try {
    const res = await fetch(`${API_BASE}/ping`, { signal: AbortSignal.timeout(1500) });
    modoOnline = res.ok;
  } catch {
    modoOnline = false;
  }
  actualizarIndicadorModo();
  return modoOnline;
}

// Carga de tiquets: API o localStorage según modo
async function cargarTiquets(filtros = {}) {
  if (modoOnline) {
    const params = new URLSearchParams(filtros);
    const data = await fetch(`${API_BASE}/tiquets?${params}`).then(r => r.json());
    return data.tiquets;
  } else {
    // Fallback: leer de localStorage (misma estructura JSON)
    const raw = localStorage.getItem('codanor_tiquets_v2');
    return raw ? JSON.parse(raw) : [];
  }
}

// Sincronización al recuperar conexión
window.addEventListener('online', async () => {
  if (await detectarModo()) sincronizarLocalStorageConAPI();
});

Bash Backup obligatorio ANTES de ejecutar la migración 
# Ejecutar ANTES de migration_tiquets.sql — en el directorio del servidor
cd ~/Proyectos/Plataforma_Seguimiento_Proyectos/servidor

TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
sqlite3 plataforma.db ".backup 'backups/plataforma_pre_tiquets_${TIMESTAMP}.db'"

# Validar integridad del backup antes de continuar
INTEGRITY=$(sqlite3 "backups/plataforma_pre_tiquets_${TIMESTAMP}.db" "PRAGMA integrity_check;")
if [ "${INTEGRITY}" = "ok" ]; then
  echo "[OK] Backup validado. Procediendo con la migración..."
  sqlite3 plataforma.db "< migration_tiquets.sql"
else
  echo "[ERROR] integrity_check falló. NO ejecutar migración."
  exit 1
fi
